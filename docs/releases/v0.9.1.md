# dworm v0.9.1

## Fixed

- **Shells and long-running processes survive host stalls.** When the host froze
  for a minute or more (for example while thrashing under memory pressure with
  several coding agents running), the bridge's keepalive gave up after 10 seconds
  and tore down the connection to the container. Every process started through
  dworm was terminated, and the shell printed "Connection to the container lost,
  reconnecting..." followed by "Reconnected; this is a new shell". All instances
  on the host were affected at the same moment.

  The bridge now tolerates an unanswered keepalive ping, a blocked write, or an
  unacknowledged stream open for up to five minutes (previously 10 seconds, and
  75 seconds for stream opens). Keepalive stays enabled, so a hung container is
  still detected; a dead `docker exec` is still detected immediately.

## Upgrade

Run `dworm self-update`, then `dworm stop` in existing workspaces before restarting
their bridge with `dworm up`. The new timeouts apply once both the host and the
endpoint come from v0.9.1, which happens on the next start. Existing containers do
not need to be rebuilt. There is no protocol change.
