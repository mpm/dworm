# v0.6.0 — Self-update and bundled endpoints

## Highlights

- `dworm self-update` installs the latest stable release for Linux/macOS on
  amd64/arm64. Downloads require the published SHA-256 checksum; missing or invalid
  checksums fail without replacing the executable.
- Every host binary embeds Linux amd64 and arm64 endpoints. Container image
  metadata selects the correct endpoint, independent of host architecture.
- Release archives now need only the host executable. Separately installed
  endpoints are ignored, and container endpoint replacement uses an atomic rename
  so a running process keeps its executable inode.
- Symlinked installations update the resolved executable. Updates take effect on
  the next invocation; current/newer versions and active sessions are left alone.

## Installation and upgrades

Older versions do not have `self-update`: use the installer or install this release
manually once. Thereafter run `dworm self-update`. Clean stable release versions
are required; development/dirty builds are refused. Installation errors identify
the destination and release URL; directory permissions must allow replacement.

Source builds require Go 1.24.11+ and `make build-host` (or `make build`). Before
direct Go build/test commands, run `make prepare-endpoints`. Plain remote
`go install` cannot generate the embedded assets.

## Verification

Go race checks, updater HTTP fixtures, installer fixtures, all four host builds,
and isolated single-binary Docker forwarding/credential checks passed. ARM64
payloads were inspected but not run in a container; macOS was cross-built, not
runtime-tested. The broader Docker suite retains SSH/GPG environment failures and
an image-removal conflict; see `docs/RELEASING.md` for the detailed record.
