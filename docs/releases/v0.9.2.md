# dworm v0.9.2 — Full-screen applications in the shell

## Fixed

- **The shell comes back after full-screen applications.** Applications such as
  vim, less, htop or anything built on curses switch to the terminal's alternate
  screen and restore the previous screen when they exit. In `dworm shell` (and
  `dworm up` on a terminal), leaving such an application dropped the session to the
  host terminal's own screen: the status bar's screen was gone, and the next prompt
  started at the top of the window. The TUI itself runs on the host terminal's
  alternate screen, and a terminal has only one.

  dworm now keeps the application's alternate screen inside the shell area. When the
  application exits, the shell screen is repainted as it was, with the cursor (and
  text attributes) where the shell left it. To do this, dworm keeps a copy of the
  shell area in a terminal emulator
  ([`charmbracelet/x/vt`](https://github.com/charmbracelet/x/tree/main/vt)); output
  is still passed to your terminal as it arrives.
- **The cursor no longer jumps after a status bar update.** Port, state, and log
  updates redraw the status bar using the terminal's saved cursor, which is the same
  slot applications use for "save cursor" (ESC 7). An application that had saved its
  cursor continued at the wrong place. dworm now leaves the application's saved
  cursor intact.
- **Applications no longer write over the status bar.** Positioning below the
  application's last row (top does this on exit) is clamped to the shell area,
  as on a terminal of the application's size, and full-screen erases redraw the
  status bar right away.
- A terminal reset (`reset`, `tput reset`) inside the shell no longer leaves the
  TUI's screen; scroll regions set by applications are kept above the status bar.

## Performance

The terminal emulator processes printed text at a few MB/s. dworm skips output that
scrolls off the screen anyway and batches scrolling, and takes output that has
already arrived in one go. Measured with a 50 MB output flood in a 200×60 shell:
about 20 MB/s for plain text (27 MB/s before) and 19 MB/s for colored output
(9 MB/s before).

## Upgrade

Run `dworm self-update`, then `dworm stop` in existing workspaces: the client
refuses to talk to an instance of another version. The next `dworm shell` or
`dworm up` starts a v0.9.2 instance. The change itself is in the shell client;
there is no protocol change and containers do not need to be rebuilt.
