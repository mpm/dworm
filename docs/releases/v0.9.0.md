# dworm v0.9.0

## Persistent host-side Dev Container environment

Projects can now configure the host-side Dev Container CLI environment in
`.dworm.config`:

```toml
[devcontainer_env]
BUILDX_BAKE_ENTITLEMENTS_FS = "0"
```

This removes the need to repeat a command prefix for Compose/Buildx filesystem
entitlement errors involving the Dev Container CLI's temporary Dockerfile. The
example disables Bake's filesystem entitlement checks for the project's CLI
process, rather than changing global host settings.

- Applies to `dworm rebuild` and startup through `up`, `shell`, or `exec`.
- Configured strings override inherited host variables; unrelated values remain.
- Empty values are supported; variable names and values are validated before
  launching the CLI. Values are literal, with no shell expansion.
- Settings are scoped to the Dev Container CLI and its children. They are not
  forwarded into container sessions or the host environment generation command.
- Existing `.dworm.env`, `[host_env]`, and `--env` behavior is unchanged.

## Upgrade

Run `dworm self-update`, then `dworm stop` in existing workspaces before restarting
their bridge with `dworm up`. Existing containers do not need to be rebuilt to
use this feature. Host and embedded endpoint versions remain paired; there is no
protocol change.
